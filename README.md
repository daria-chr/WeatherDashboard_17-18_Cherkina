# Weather Dashboard

## Описание

Weather Dashboard — Android-приложение, которое отображает погодные данные из трёх источников одновременно. Приложение демонстрирует практическое использование корутин Kotlin для параллельной загрузки данных без блокировки UI-потока.

## Функциональность

- Отображение температуры, влажности и скорости ветра
- Параллельная загрузка данных с помощью `async/await` 
- Вычисление индекса погоды на `Dispatchers.Default`
- Автоматическое обновление данных каждые 10 секунд
- Индикаторы загрузки для каждой карточки отдельно
- Симуляция и обработка ошибок без краша приложения
- Текстовый индикатор прогресса загрузки

## Технологии и библиотеки

- Kotlin Coroutines
- Jetpack Compose
- ViewModel + StateFlow
- lifecycle-viewmodel-compose
- MVVM-архитектура

## Ответы на контрольные вопросы

### A) В чём разница между `launch` и `async`?

`launch` запускает корутину и не возвращает результат — используется когда нужно просто выполнить задачу (например, сохранить данные, отправить лог). Возвращает `Job`.

`async` запускает корутину и возвращает `Deferred<T>` — используется когда нужен результат выполнения. Результат получают через `.await()`.

```kotlin
viewModelScope.launch {
    saveDataToDatabase()
}

val temperatureDeferred = async { repository.fetchTemperature() }
val temperature = temperatureDeferred.await()
```

### B) Что такое suspend-функция?

`suspend`-функция — это функция, которая может **приостановить** своё выполнение, не блокируя поток, и возобновить его позже. Вызывать её можно только из другой `suspend`-функции или из корутины.

Из обычной функции вызвать `suspend`-функцию **нельзя** — компилятор выдаст ошибку.

`delay()` не блокирует поток потому, что это `suspend`-функция: она приостанавливает корутину и освобождает поток для других задач, а через указанное время корутина возобновляется. В отличие от `Thread.sleep()`, который блокирует поток целиком.

```kotlin
fun bad(): String {
    Thread.sleep(2000)
    return "result"
}

suspend fun good(): String {
    delay(2000)
    return "result"
}
```

### C) Зачем нужны разные диспетчеры?

Разные диспетчеры определяют, **на каком потоке** выполняется корутина. Это важно, чтобы не блокировать UI и использовать подходящий поток для каждого типа задачи.

- **`Dispatchers.Main`** — UI-поток. Используется для обновления интерфейса (изменить текст, показать данные).
- **`Dispatchers.IO`** — поток для ввода/вывода. Используется для сетевых запросов, работы с базой данных, чтения файлов.
- **`Dispatchers.Default`** — поток для вычислений. Используется для сортировки больших массивов, сложных расчётов, обработки данных.

Если выполнить тяжёлое вычисление на `Dispatchers.Main` — UI **зависнет** на всё время вычисления, приложение перестанет реагировать на действия пользователя, и система может показать диалог ANR (Application Not Responding).

```kotlin
suspend fun calculateWeatherIndex(): Int {
    return withContext(Dispatchers.Default) {
        var result = 0
        for (i in 1..1_000_000) result += i
        result
    }
}
```

### D) Что произойдёт, если не обработать исключение в корутине?

Если исключение в корутине не обработано — приложение **крашнется** с `FATAL EXCEPTION`. Особенно опасно это при использовании `async`: исключение возникает в дочерней корутине до вызова `await()` и немедленно всплывает в родительскую, минуя `try-catch`.

Корректный способ — оборачивать `async`-корутины в `coroutineScope`, а весь блок — в `try-catch`:

```kotlin
viewModelScope.launch {
    try {
        coroutineScope {
            val tempDeferred = async { repository.fetchTemperature() }
            val humDeferred = async { repository.fetchHumidity() }
            val temperature = tempDeferred.await()
            val humidity = humDeferred.await()
        }
    } catch (e: Exception) {
        _weatherState.value = _weatherState.value.copy(
            isLoading = false,
            error = "Ошибка: ${e.message}"
        )
    }
}
```

`coroutineScope` при ошибке в одной дочерней корутине отменяет остальные и пробрасывает исключение в `catch`, не затрагивая родительскую корутину.

### E) Как работает автоматическая отмена корутин?

`viewModelScope` — это `CoroutineScope`, привязанный к жизненному циклу `ViewModel`. Когда `ViewModel` уничтожается (пользователь уходит с экрана), `viewModelScope` автоматически отменяет все запущенные в нём корутины. Это предотвращает утечки памяти и лишнюю работу в фоне.

Корутины отменяются автоматически когда:
- `ViewModel` уничтожается (вызывается `onCleared()`)
- Пользователь закрывает экран или приложение
- Activity/Fragment пересоздаётся

```kotlin
init {
    loadWeatherData()
    startAutoRefresh()
}

private fun startAutoRefresh() {
    viewModelScope.launch {
        flow {
            while (true) {
                delay(10_000)
                emit(Unit)
            }
        }.collect {
            loadWeatherData()
        }
    }
}
```
